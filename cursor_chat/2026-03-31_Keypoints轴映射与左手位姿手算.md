# Keypoints 轴口头映射 + 左臂平移能否得到 UI 位姿

## 结论摘要

- **仅**用「对方的 y→我方 x、x→z、z→y」再加左臂平移 **(1.55, 0.5653, -0.283628)**，**不能**唯一、正确地推出工程里与 MoveIt/`base_link` 一致的位姿；必须按 **TF 链**（`camera→sensor_link` 四元数 + `base_link→camera` 或 `sensor_link→left_arm_base`）做旋转与平移，与 `keypoint_arm_tf.launch.py` 一致。
- 给的 **整段 YAML 里最后一个关键点**（camera 下 x≈1.23, y≈2.86）经当前 **`tf_under` 静态树**变到 `base_link` 约为 **(1.314, -0.566, 1.513)**，与目标 **(1.233, -0.623, 0.283)** **差很多在 z**，说明 UI 上那组数**不是**该末端点直接变换结果。
- **camera 下第 3、8 号点**（0-based 索引 **2 与 7**，坐标接近）经同一 TF 得到 **(1.258, -0.566, 0.248)**，与 **(1.233, -0.623, 0.283)** 的误差约 **7 cm 量级**，更接近「中间/某索引关键点」或融合中心线与单点略有偏差。
- **四元数 (0.707, 0, 0, 0.707)**：不能从该条消息里的 `euler_angles` **直接一步**得出；工程里它是与 `/object_pose`（桥接）对齐的**标定约定**，在节点里通过 **`q_corr` 左乘**等方式对齐（见 README / `keypoint_to_arm_tf_node` 注释）。
- **时间**：`header.stamp.sec = 1774948498` 在本地时区对应 **2026-03-31 17:14:58**，与 **17:16:31** 相差约一分半，需用**同一帧** stamp 或对钟，不能单凭该条 YAML 严格对上 17:16:31。

## 假设

- 静态 TF 取仓库 `tf_under_manipulator` 分支：`base_link→camera` 平移 (-1.55,-0.5653,0.283628)、四元数 (0.5,0.5,0.5,-0.5)；`camera→sensor_link` 为 (0.5,0.5,0.5,0.5)；父子关系与 `static_transform_publisher` 约定一致。
